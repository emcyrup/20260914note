# 放課後等デイサービス業務支援システム v2

放課後等デイサービス事業所の職員向け業務支援Webアプリケーションです。

## 主な機能

- 利用者台帳（受給者証・保護者管理・OCR読み取り）
- 予定管理（月次カレンダー・一括生成・ステータス管理）
- 日次記録（AI文章整え・音声入力・電子サイン・LINE配信）
- 個別支援計画（アセスメント → 原案 → 担当者会議 → 説明・同意・交付 → モニタリング の5ステップ制。前のステップが完了しないと次に進めず、各ステップの残り項目をチェックリストで表示）
- 請求管理（請求マトリックス・上限額管理・請求書PDF・領収書PDF）
- LINE連携（保護者向けメッセージ配信・Webhook）
- 施設設定（タグ管理・加算マスタ）
- 画面の着せ替え（スタンダード／大きな文字／スタイリッシュ／かんたん3ステップ。職員ごとに割り当て可、記録は共有のまま）
- AI加算提案（日誌を保存すると算定できそうな加算を提案。「採用する」で請求マトリックスへ反映）
- AIチャットボット（右下の💬。利用者の出席日数・最近の様子、加算の要件などを質問）
- 算定要件資料（PDF をアップロードして「ベクトル化」すると、加算提案とチャットが資料を根拠に答える）
- AI が出した観察の観点に「はい／いいえ」を付け、その結果をもとに考察を作り直せる

## 画面の着せ替え

サイドバー下の「画面の見た目」（`/accounts/theme/`）で、同じ記録を共有したまま見た目を切り替えられます。管理者は職員ごとに割り当てできます（管理画面の職員アカウントにも「画面の見た目」欄があります）。

| 画面 | 向いている人 | 内容 |
|---|---|---|
| スタンダード | どの事業所でも | 標準の画面。ホームには今週の来所状況（人数と日誌の作成状況）が出ます |
| 大きな文字 | パート職員・年配の方 | 文字を約1.6倍、ボタンを大きく、請求・設定などの項目を隠し、コントラストを上げる |
| スタイリッシュ | 見せる場面が多い事業所 | 濃色の背景で装飾を抑える |
| かんたん3ステップ | とにかく迷わせたくない現場 | メニューを隠し「きょうの きろく」（`/records/simple/`）に今日来る子だけを並べる。①メモを入れる ②下書きをつくる ③確認して確定 の3つだけ |

### 細かい設定（フォント・ダークモード・背景色・文字の大きさ）

「画面の見た目」ページの下の「細かい設定」で、4パターンとは独立に自分だけの表示を変えられます。

| 項目 | 選べるもの |
|---|---|
| フォント | BIZ UDPゴシック（標準）／Noto Sans JP／M PLUS Rounded 1c（丸ゴシック）／Noto Serif JP（明朝）／端末の標準 |
| ライト／ダーク | ライト／ダーク／端末の設定に合わせる（ダークはどのパターンでも使えます） |
| 文字の大きさ | 90／100／115／130% |
| 背景色 | プリセット9色、または好きな色（カラーピッカー）。「標準」でテーマの色に戻る |

保存前にプレビューで確かめられます。設定は職員ごとに保存され、端末を変えても同じ見た目になります。

## 日誌の観点（はい／いいえ）

活動名から AI が「めあて」と観察の観点を出します。観点ごとに「はい」（できていた）「いいえ」（できていなかった）を付け、「はい／いいえを反映して考察を作り直す」を押すと、その結果を事実として考察を書き直します。観点は手で追加・修正・削除でき、日誌の詳細と かんたん3ステップ画面にも表示されます。

## 日誌テンプレート（ある利用者の日誌を他の利用者でも使う）

- 日誌の詳細右上の <i>ファイル</i> ボタン（テンプレートにする）で、その日誌を施設共通のテンプレートとして保存します。活動・めあて・観点（はい／いいえは空に戻す）・記録文・保護者向けメッセージ・タグ・5領域を引き継ぎ、写真・時刻・体調は含みません。
- 保存時に、元の利用者の姓名・名・姓（かな含む）は文中で `{名前}` に置き換えられます。他の利用者の「日誌を追加」「編集」の上部にある「テンプレートから入力…」→「反映」で、その利用者の名前に置き換えた内容がフォームに入ります。
- 「記録」画面右上の「テンプレート」から一覧・編集（文面・観点・タグ・5領域）・削除ができます。使用回数の多い順に並びます。テンプレートは施設ごとに分かれ、他施設からは見えません。

## AI加算提案・チャットボット・算定要件資料

すべて `ANTHROPIC_API_KEY` が必要です（未設定なら何もしません）。

- **AI加算提案**: 日誌を保存すると、日誌の内容（タグ・記録文・送迎の有無）と個別加算の一覧、資料の抜粋をもとに、算定できる可能性のある加算を提案します（`AI_ADDON_SUGGESTIONS=False` で停止）。日誌の詳細の「AI加算提案」欄で「採用する」を押すと請求マトリックスのセルに加算が入り、未確認（◆）に戻ります。ポップアップで確認・保存してください。「見送る」で除外、どちらも取り消せます。「提案を作り直す」で再判定します
- **AIチャットボット**: 画面右下の💬。質問に利用者名が含まれると、その利用者の今月の出席・欠席、受給者証、支援計画の目標、直近5件の日誌を参考情報として答えます。同じ名前の利用者が複数いるときは選択肢を出します。加算の質問には加算マスタと資料の抜粋を根拠にします。会話はブラウザのタブを閉じるまで保持されます。「かんたん3ステップ」画面では表示しません
- **算定要件資料**: 施設設定 → 「算定要件資料」で PDF（30MB まで、文字が埋め込まれたもの）をアップロードし「ベクトル化する」を押します（管理者のみ）。文字を取り出して 600 字前後の断片に分け、文字バイグラムの BM25 で検索できるようにします。外部の埋め込み API は使わないため追加のキーは不要です。資料が無くても動きますが、AI が一般知識だけで判断するため精度が下がります

## 職員・運用管理、呼び方・ロゴ・配色

- **職員・運用管理**（管理者のみ、サイドバー「設定」の下）：職員の追加（ログインID・表示名・権限区分・画面・初期パスワード）、編集、パスワード再設定、無効化。退職者は削除せず無効にすると記録者名が残ります
- **呼び方・ロゴ・配色**（施設設定 → 施設基本情報）：「職員」「利用者」の呼び方（支援員／利用児 など）をメニューと主な見出しに反映。ロゴ画像はサイドバーに、コーポレートカラーは見出し・ボタン・進捗の色に反映されます
- 呼び方は、サイドバー・各画面の見出し・表の列名・空のときの案内・保存時のメッセージ・ページタイトルまで置き換わります（法令上の用語「児童発達支援管理責任者」「利用者負担上限額」などはそのままです）。

## 別の事業所（施設）を追加する

記録・利用者・計画・請求は施設ごとに完全に分かれ、職員は1つの施設にだけ所属します。同じアプリ内に事業所を増やすには、サーバーで次を実行します。

```bash
python manage.py create_facility "あおば教室" --admin aoba_admin --password '初期パスワード' \
    --copy-settings-from 1      # 既存施設（ID）の呼び方・配色・使う機能・日誌の項目順・単位数をコピー（任意）
    # --office-number 1234567890  --display-name "管理者名"  --demo（架空データも投入）
```

標準の活動タグ・支援内容タグが入り、管理者アカウント（権限区分＝管理者）ができます。その管理者でログインし、施設設定で事業所番号・呼び方・使う機能を確認してから、「職員・運用管理」で職員を追加してください。`/admin/`（Django 管理画面）の「施設」「職員アカウント」から手で作ることもできます。

## 予約管理（1日の枠・キャンセル待ち・公式LINEからの申し込み）

施設設定 →「使う機能」で **予約管理** を入れると、サイドバーに「予約」が出ます。1日あたりの枠を、職員のカレンダー入力と公式LINEからの申し込みの両方で埋め、予約が増減したら通知を積みます。

- **枠**：1日あたり（時間帯では分けません）。既定は10人で、予約カレンダーの下の設定で変えられます（管理者のみ）。休業曜日と臨時休業日は枠0で、予約を受け付けません
- **予約は利用者1人につき1件**（1件＝枠1つ）。きょうだいで2人来る日は2件になります。同じ日・同じ利用者の重複は受け付けません
- **満枠のとき**：キャンセル待ちで受けます（設定で断ることもできます）。取消で空いたら、キャンセル待ちを**申し込み順に**確定します
- **顧客（予約の連絡先）**：保護者台帳とは別の台帳です。1人の顧客が複数の利用者を担当でき、通知の宛先はここで決まります
- **通知**：受付・キャンセル待ち・繰り上げ確定・取消・お断り・前日のお知らせ・空き枠。文面は事実（日付・利用者・状態）だけで、末尾に署名が付きます。**積むだけで、送信は職員が「送信待ちをまとめて送る」を押したとき**です（設定で反映直後に送ることもできます。既定は off）。LINE未連携の相手は「コピーして送る」に残ります
- **空き枠のお知らせ**：満席だった日に空きが出て、キャンセル待ちの繰り上げでも埋まらなかったときに、LINE連携ずみでその日に予約のない顧客へ積みます（その予約の相手は除き、同じ日・同じ相手には重ねません）。きっかけは **取消・削除・日にちの変更・1日の枠を増やしたとき** の4つです。その日の画面の「空きのお知らせを送信待ちに入れる」でいつでも出せます。自動のお知らせは設定「満席から空きが出たら、顧客へお知らせする」で止められます（職員が押したときは設定に関わらず積みます）。`RESERVATION_SITE_URL` を決めているか、画面から操作したときは、文面にその方のご予約ページのリンクが付きます
- **予約の増減をスタッフのグループへ**：日付・利用者・何が起きたか・その日の予約数だけを送ります。保護者の名前と連絡先は書きません。お知らせ先のグループは、公式LINEの画面に届いた投稿から選びます（IDを手で写す必要はありません）

- **予約の変更・削除**：日を開いて「変更」で日にちと備考を変えられます。もとの日はキャンセル待ちを繰り上げ、顧客へ変更のお知らせを積みます。「削除する」は、間違って入れた予約を記録ごと消すためのもので、顧客へのお知らせは送りません

### 顧客向けの予定表（ログインなしのページ）

事業所と顧客のどちらからでも予定表を見られます。アドレスそのものが合い言葉で、検索には載せません（`noindex`）。

| ページ | 何ができるか | アドレスの確認場所 |
|---|---|---|
| 空き状況 | 月ごとの空き（○△×）と、**お申し込み**（予約している方の名前は出ません） | 予約カレンダー → 予約の決まりごと |
| 顧客ごとのページ | 自分の予約の確認・申し込み・取り消し | 顧客 → 編集 |

#### 予約の受け方（来た順に自動 ／ 職員が確認）

予約カレンダー下の設定「**予約の受け方**」で、申し込みの扱いを決めます（既定は**来た順に自動で確定する**）。

| | 来た順に自動で確定する（既定） | 職員が確認してから確定する |
|---|---|---|
| 顧客ページ・空き状況ページ・公式LINE | 届いた順にその場で確定 | 「予約 → 申し込み」に積み、職員が押したときだけ確定 |
| 同じ枠に同時に申し込みが来たとき | **先に届いた方が確定**。あとの方はキャンセル待ち、受けない設定なら「満席のため、ご予約をお受けできませんでした」とその場でお伝えする | 同左（職員が反映する順） |
| 台帳にいないお名前 | **「台帳に未登録」のまま席を押さえます**。その日の画面に「台帳に未登録」と出るので、台帳に登録したら「結びつける」を押します | 職員が利用者を選んで確定 |

枠の取り合いは、その日の予約行をデータベースで押さえてから数えるので、同時に来ても枠を超えません（先に押さえた方が確定）。

空き状況のページはアドレスを知っている方なら誰でも申し込めるため、自動投稿よけの見えない欄と、同じ相手から1時間5件までの制限があります。見送り・顧客台帳への追加・記録の削除は「予約 → 申し込み」の画面で行います。

- 受け付ける範囲（何日先から・何日先まで）と、そもそも申し込みを受けるかは設定で変えられます。満枠の日はキャンセル待ちでお預かりします
- 顧客は、自分が担当する利用者のぶんだけ見られます。ほかの家庭の予約は見えず、取り消せません
- **アドレスを1字でも書き換えると開けません。** アドレスの後半は署名（`SECRET_KEY` による HMAC）で、DB を引く前に確かめて 404 にします。署名の鍵はページの種類ごとに分けてあるので、空き状況のアドレスを顧客ページに貼っても（その逆でも）通りません
- アドレスは、渡した先が変わったときなどに作り直せます（前のアドレスは開けなくなります）。`SECRET_KEY` を変えたときは `python manage.py reissue_reservation_tokens --only-broken` で作り直します

### 公式LINEからの申し込み

公式LINEに届いた文は**受信箱に積むだけで、自動では確定しません**。公式LINEの画面で読み取り（予約か取消か・日付・利用者）を確かめ、「反映する」を押したときに予約になります。日付か利用者が決まらないものは反映せず、職員が画面で選びます。`【登録】` で始まる文は顧客の登録の申し込みとして扱い、「顧客として登録」で台帳に入ります。担当する利用者は自動で結びつけません（名前の一致だけで決めると別人になりうるため）。取り込みずみにした受信は、本文と表示名をその場で消します。

Webhook の URL は事業所ごとで、施設設定の LINE 欄と、予約の「公式LINE」画面に表示されます。予約管理を使わない事業所では、これまでどおり登録コードの照合だけを行います。

### 「予約」と送られたら、予定表のアドレスを返す

公式LINEに「予約」「空いてますか」などのお問い合わせが届いたら、**顧客向け予定表のアドレスを自動でお返しします**（設定は不要）。

- 顧客台帳にいる方（LINEのユーザーIDが登録ずみ）……その方専用のページ。確認・申し込み・取り消しができます
- はじめての方……空き状況のページ（公開しているときだけ）。お申し込みができます
- 日にちが書かれた文（例「9/20 予約おねがいします」）は、これまでどおり受信箱にも積み、返信ではアドレスもあわせてお知らせします
- 取り消しのお問い合わせは、顧客台帳にいる方にだけページをお返しします（はじめての方は職員が対応）

アドレスの入口は `RESERVATION_SITE_URL` を決めていればそれを使い、無ければ Webhook を受けたホストから組み立てます。

### LINE の投稿をそのまま予約にする（顧客・スタッフのグループ）

「予約の設定 → 公式LINEから直接受ける」で、読み取れた投稿をその場で反映できます。

- **顧客（公式LINEへのメッセージ）**：受け方が「来た順に自動」のとき、顧客台帳にいる方が日にちとお子さまの名前を書いて送れば、その場で予約になり LINE に返事をします（`9/20 予約おねがいします` / `9/20 キャンセルします` / `空いてますか？`。1通に5日まで）。受け付ける範囲の外や、担当していない利用者の名前は反映せず、受信箱へ回します
- **スタッフのLINEグループ**：お知らせ先に登録したグループの投稿だけを見ます（`9/20 青木はると 予約` / `9/20 青木はると キャンセル` / `9/20 空き`）。名前と日にちが読み取れない投稿と、登録していないグループの投稿は受信箱に積むだけです。既定は on

どちらも、読み取れなかった文は受信箱に積み、職員が確かめてから反映します。

### 予約のサンプルデータ

`python manage.py seed_demo --facility <ID>` を予約管理を使う事業所で実行すると、利用者・日誌などに加えて予約のサンプルも入ります。

- 顧客台帳6件（保護者を連絡先として。LINE は未連携なので、通知は「コピーして送る」に残ります）
- これから2週間の予約（利用曜日どおり）と、満席の日のキャンセル待ち1件
- 臨時休業日1件（来週の土曜・職員研修）
- 空き状況ページからの申し込み2件（1件は在籍者と名前が一致、1件ははじめての方）
- 公式LINEの受信1件（未処理）と、送信待ちの通知3件

1日の枠がまだ既定（10人）で予約が1件も無いときだけ、様子が分かるように **3人** に変えます（あとから設定画面で戻せます）。`--reset` で入れ直すと、サンプルの顧客・申し込み・受信・臨時休業日もきれいに消えます。

### 予約管理だけを別サーバーで動かす（横展開）

環境変数 `RESERVATION_ONLY=True` を立てると、同じコードのまま**予約だけのサービス**として動きます。サイドバーは「予約カレンダー／顧客／公式LINE／職員・運用管理」だけになり、記録・請求・支援計画などの URL は載りません。手順は [docs/RESERVATION_STANDALONE.md](docs/RESERVATION_STANDALONE.md) を見てください。

## 自分でアカウントを作る（招待リンク・新しい事業所の登録）

**職員の登録は招待リンクで行います。** 管理者が「職員・運用管理」→「招待リンクを発行」で権限区分・使える回数・有効期限を決めて URL を発行し、本人に渡します。本人はその URL を開いてログインID・表示名・パスワードを決めれば、その事業所の職員としてすぐにログインできます。リンクは回数を使い切るか期限が過ぎると無効になり、管理者はいつでも取り消せます。誰でも登録できるリンクなので、公開の場所には貼らないでください。

**新しい事業所をログイン画面から登録**することもできます（事業所と管理者アカウントを同時に作り、標準タグを入れます）。既定では無効なので、使う場合は `.env` に次を設定します。

```
ALLOW_FACILITY_SIGNUP=True   # ログイン画面に「新しい事業所として登録する」が出る
SIGNUP_CODE=xxxx             # 任意。設定すると、このコードを知っている人だけが登録できる
```

事業所名が同じものは登録できません。登録後は施設設定に移動するので、呼び方・使う機能を確認し、招待リンクで職員を招いてください。パスワードは Django の標準ルール（8文字以上、ログインIDや名前と似ていない、よくある文字列でない、数字だけでない）で確認します。

## 同時編集の競合対策（複数の職員が同じ画面を編集するとき）

日誌・支援計画の各ステップと目標・利用者／保護者／受給者証・施設設定・日誌テンプレート・メモ・事業所様式・上限額管理の編集フォームには、次の 2 つの仕組みがあります。

- **編集中の表示**：フォームを開いている間、45 秒ごとにサーバーへ知らせます（`/editing/`）。同じものを開いている他の職員がいると、フォームの先頭に「○○さん（HH:MM から）も同じ画面を編集中です」と出ます。閉じるか 2 分経つと消えます。
- **保存時の版の確認（楽観ロック）**：フォームには開いた時点の版（`updated_at`）が隠し項目 `version` として入っています。保存の直前に画面側でサーバーの版を確かめ、開いたあとに他の職員が保存していれば「上書きして保存する／やめる」の確認を出します。サーバー側でも同じ確認を行い、版が違えば保存を止めてメッセージを出します（Django フォームの画面では入力を保持したまま「それでも上書きして保存」のチェックが出ます）。`force_save=1` を付けた送信だけが上書きできます。
- 日誌の新規作成で同じ日の日誌がすでにある場合（他の職員が先に作った）は黙って上書きせず、その日誌を開くよう案内します。
- `version` を送らない古い画面や外部からの POST は従来どおり保存されます。

実装は `config/concurrency.py`（`check_conflict` と対象の登録 `KINDS`）、`facilities/views.py` の `EditingView`、`static/js/concurrency.js`、テンプレートタグ `{% version_field obj %}` と `data-concurrency="種類:ID"` です。新しい編集フォームを作るときは、この 3 つを付けるだけで対応できます。

## 開発向けユーザー（複数の事業所を切り替えて確認する）

職員は1つの事業所にだけ所属しますが、**開発向けユーザー**はすべての事業所を見られ、サイドバー上部の「開発向け：いまの事業所」で事業所を切り替えて、その事業所の職員として画面の動きを確認できます（DB 上の所属は変わりません。切り替えはログインしているブラウザのセッションだけに効きます）。

```bash
python manage.py set_developer <ログインID>          # 付与
python manage.py set_developer <ログインID> --off    # 解除
```

`/admin/` の「職員アカウント」→「開発向けユーザー」でも付け外しできます。スーパーユーザー（`createsuperuser`）は最初から切り替えられます。所属の無い開発向けユーザーは最初の事業所で動きます。

## 事業所ごとの帳票様式（はぴねす様式）

施設設定 →「使う機能と、日誌で AI が作る項目」→「帳票様式」で **はぴねす様式** を選ぶと、その事業所だけにサイドバー「事業所様式」が出ます（他の事業所には影響しません）。「帳票様式」の選択は**開発向けユーザーにだけ表示**されます（各事業所の管理者に他の事業所の様式名を見せないため）。その事業所の管理者には「専用の様式を使っています」とだけ出ます。

サンプルデータを入れると（`seed_demo --facility <ID>`）、はぴねす様式の施設には報告書2件・専門的支援実施計画書2件と、計画書の様式追加項目も一緒に入ります。

| 様式 | 作り方 |
|---|---|
| 関係機関連携加算Ⅱ 報告書 | 「事業所様式」→ 作成。児童・会議日時・場所・形式・参加者（最大8名）・目的・結果・意見・対応方針・記録者を入力 → PDF |
| 専門的支援実施計画書 | 「事業所様式」→ 作成。想定支援期間・希望・身体機能（関節可動域・疼痛・筋力低下・バランス・呼吸循環・筋緊張）・基本動作（自立／一部介助／介助／非実施）・ABMS-C・重要領域・達成目標・支援内容（訓練の選択）・実施内容・説明日 → PDF |
| 個別支援計画書（別紙1） | 支援計画のデータから自動作成。目標ごとの「項目・担当者・留意事項」と「支援の標準的な提供時間」は計画の「様式の追加項目」で補う。2ページ目に説明・同意欄（電子サインがあれば署名画像） |

各様式は「画面で見る」（印刷確認）と PDF の両方で出せます。レイアウトは `templates/custom_forms/pdf/` にあります。

## 使う機能の選択、日誌の項目の順番

施設設定 →「使う機能と、日誌で AI が作る項目」（管理者のみ）で次を設定します。

- **使う機能**：請求機能（請求マトリックス・上限額管理・請求書・AI加算提案）と LINE 連携を、それぞれ使う／使わないにできます。使わない機能はメニュー・ボタン・設定欄から消え、URL を直接開いてもホームに戻ります。記録は消えません。既存の施設は「使わない」で始まります（新しく作る施設は「使う」）。
- **日誌の項目と順番**：AI が作る項目（活動・めあて・観点・考察／観察・活動内容／支援内容／本人の反応／保護者向けメッセージ）の使う・使わないと順番を決めます。日誌の入力・詳細画面はこの順番で並び、AI の一括生成は上の項目ほど優先して丁寧に書きます。

## 紙の日誌の取り込み（カメラ）

「記録」→「紙の日誌を取り込む」（ホームのクイックアクセスにもあります）で、過去の紙の日誌をスマートフォンのカメラで撮るか画像を選んで取り込みます。

1. 写真を取り込む（1回に 20 枚まで。1枚に1日分）
2. 「AIで読み取る」で、日付・利用者名・入退室時間・体調・活動・めあて・観点（○×）・観察・支援・反応・考察・保護者向けの各項目に分けます。読めなかった箇所は「読めない箇所」として表示します
3. 写真を見ながら内容を確認・修正し、「日誌として保存」。写真は日誌に添付され、同じ日の日誌がすでにある場合は上書きの確認が出ます

読み取りには `AI_PLAN_MODEL`（既定 `claude-opus-5`）の画像入力を使います。画像は送信前に長辺 1600px に縮小します。

## AI が作る文章の品質

AI が生成する記録文（日誌の一括生成・文章整え・めあて／考察、支援計画の下書き、加算提案、チャット）には共通の「日本語の書き方」ルールを付け、返答は `ai_assist/text.py` の `clean_ai_text` で整えてから画面に入れます（文字のまま残ったエスケープや半角カタカナ、ゼロ幅文字、マークダウン、先頭のラベルを除去）。文章生成のモデルは既定で `claude-opus-5` です。費用を抑えたい場合は `.env` に `AI_TEXT_MODEL=claude-sonnet-5` を指定してください。

## 個別支援計画の進め方

サイドバー「支援計画」→「新しい計画を作る」で利用者を選ぶと、次の5ステップを順番に進めます。

| ステップ | 完了に必要な項目 |
|---|---|
| 1. アセスメント | 面談日／面談相手／心身の状況／置かれている環境／希望する生活 |
| 2. 計画（原案）の作成 | 計画期間／総合的な支援の方針／長期目標（達成時期）／短期目標（達成時期・具体的な支援内容） |
| 3. 担当者会議 | 開催日／出席者／本人の出席（欠席なら理由）／協議内容／修正の有無（修正した場合は内容） |
| 4. 説明・同意・交付 | 説明日と相手／文書での同意（電子サイン、または書面の署名者と同意日）／本人・家族への交付／相談支援事業所への交付／サービス開始日 |
| 5. モニタリング | 初回の面談記録。以後は記録ごとに次回期限を設定し、期限超過は一覧と利用者ページに表示（間隔の既定は3か月） |

- 各ステップは「途中保存」でいつでも保存でき、右側のチェックリストに残り項目が出ます。すべて揃うと「保存してステップNを完了」で次へ進みます
- 完了したステップは読み取り専用になります。修正したいときは直前に完了したステップだけ「完了を取り消して修正」できます（さらに先へは進めなくなります）
- ステップ4の完了でサービス開始（実施中）になり、ステップ5で見直しが必要になったら「次の計画を作成」で第2期を始められます（前回のアセスメントを引き継ぎ、新しい計画の交付で前の計画は終了）
- 「計画書」「計画書PDF」で交付用の計画書（署名欄つき）、ステップ5では「モニタリング報告書」と PDF を出力できます
- **AI の下書き**（`ANTHROPIC_API_KEY` が必要）：ステップ1「過去の日誌から AI で下書き」で直近の日誌から心身の状況・環境・希望の下書きを入れます。ステップ2「期間の日誌から AI で原案の下書き」で方針と目標を下書きし、根拠になった日誌を目標にひもづけます。下書きは編集して完了するまで計画になりません
- **根拠になった記録**：各目標の「選ぶ」で期間内の日誌を関連度順に並べ、根拠としてひもづけられます。計画書と PDF に根拠の日付が出ます
- 日誌画面の左メニュー「モニタリング」「アセスメント」「計画書をつくる」から、その利用者の進行中の計画に移動できます

## LINE Webhook の設定

デプロイ後、以下の手順でLINE連携を有効にしてください。

1. 施設設定画面でLINEチャネルアクセストークン・シークレットを入力
2. LINE Developers ConsoleでWebhook URLを登録
   - URL: 施設設定の LINE 欄に表示される **事業所ごとの URL**（`https://<ドメイン>/line/webhook/<事業所ID>/`）。事業所ごとに LINE 公式アカウント（チャネル）を分けます
   - 「Webhookの利用」をONにする
   - 「応答メッセージ」はOFFにする
3. 保護者の連携：利用者ページの保護者欄にある **登録コード（8文字・発行から72時間有効・1回限り）** を保護者に伝え、公式アカウントに送ってもらいます。期限が切れたら「再発行」。間違いが5回続いた LINE ユーザーは1時間受け付けません

### アップロードファイル（写真・スキャン・署名・資料）の保護

`/media/...` は Django が配信し、**ログイン中の職員の事業所のファイルだけ**を返します（他の事業所や未ログインは 404／ログイン画面）。ファイル名は UUID に置き換えて推測できないようにしています。LINE に写真を送るときだけ、30 分で失効する署名つき URL を渡します。前段の nginx / Caddy で `/media/` を直接配信しないでください。PDF 生成（WeasyPrint）は HTTP ではなくサーバー内のファイルを直接読みます。
