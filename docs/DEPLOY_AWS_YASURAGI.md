# 介護施設「やすらぎの森」の環境（ゆあーず・オウル・コトと同じ AWS 共用サーバー・別ポート・別 DB）

対象（**仮**。2026-10-31 時点でプロバイダ側の nginx・ポート・DB は準備中。決まったらこの表と Secrets を直す）:
`https://kaigonote.yasuragi.ai-labo.cloud/` → プロバイダ管理の nginx（HTTPS 終端）→ Gunicorn `0.0.0.0:8047` → プロバイダ管理の PostgreSQL（DB `kaigonoteyasuragi`、ユーザー `ai_labo_dbuser`）。

やすらぎの森の機能（画面の型「介護施設」・`nursing` アプリ）は **`yasuragi` ブランチ**にあります（コトの `kyotaku` ブランチから分けた。介護保険証・家族の形はコトと共通）。ゆあーず・オウル（`ryoiku`）には入れません。共通部分の修正は `ryoiku` → `kyotaku` → `yasuragi` の順に取り込みます。

コト（`docs/DEPLOY_AWS_KOTO.md`。`~/kaigonotekoto`・8043・DB `kaigonotekoto`）と**同じサーバー・同じ仕組み**で、置き場所・ポート・DB・`.env`・ブランチが違うだけです。venv（`~/env`）はゆあーず・オウル・コトと共用します。DB が別なので、やすらぎの森の利用者・記録はほかの事業所からは見えません。

| | コト | やすらぎの森（仮） |
|---|---|---|
| アドレス | `kaigonote.koto.ai-labo.cloud` | `kaigonote.yasuragi.ai-labo.cloud` |
| 置き場所 | `~/kaigonotekoto` | `~/kaigonoteyasuragi` |
| Gunicorn | `0.0.0.0:8043` | `0.0.0.0:8047` |
| DB | `kaigonotekoto` | `kaigonoteyasuragi`（`ai_labo_dbuser`。ゆあーずと同じユーザー・同じパスワード） |
| ブランチ | `kyotaku` | **`yasuragi`** |
| 配備 | Deploy (koto) | **Deploy (yasuragi)**（Actions から手で。ブランチ `yasuragi` を選ぶ。push では動かない） |
| 管理 | Manage (koto) | **Manage (yasuragi)** |

秘密情報（DB パスワード、`SECRET_KEY`、Anthropic キー、SSH 秘密鍵、管理者のパスワード）はサーバーの `.env`・GitHub Secrets だけに置きます（リポジトリ・Notion・Actions のログには書かない）。DB パスワードはゆあーずと同じユーザーなので、初回の配備でサーバーの中で `~/michinoteyours/.env` から写します。

## 画面と機能（画面の型「介護施設」＝ `Facility.LAYOUT_CARE`、`create_facility --preset care`）

2026-10-20 の打ち合わせの要望を、まず「よく使う機能」から（出荷時 40 点 → 現場の声で半年かけて仕上げる）。

- **ホーム**：きょうの検温板の記入数・介護記録の未記入／確認待ち／承認ずみ・検温板で注意のある人・ヒヤリ／事故報告の未承認・薬の更新の期限・計画書の見直し時期・きょうの人員配置
- **検温板**（`/care/vitals/`）：全員を一覧で入れてまとめて保存（朝／夕）。体温・血圧・脈拍・SpO2・主食／副食（割）・水分・排尿／排便・入浴・特記。実測なので AI は使わない。発熱（施設設定で変えられる。既定 37.5℃）・血圧・脈拍・SpO2 の注意は赤。利用者ごとに **1 人 1 週間 1 枚**（紙の検温板と同じ形）の表と折れ線グラフ。A4 横で印刷（1 人分・全員分）
- **介護記録**（`/care/records/`）：「はい／いいえ」9 項目・キーワード・メモ（音声入力。母国語や単語の並びでもよい。入力の言語を選ぶ）→「AI で下書き」で介護記録（既定 250 字。常体）と家族向けのメッセージ（です・ます）ができる。その日の検温板の実測・要介護度も材料にする。外国語で入れたときは確認用の訳も出す。「日本語に整える」で欄ごとに正式な日本語へ。**下書き → 確認へ出す → リーダー・管理者が承認**（ワンクリック。戻すときはひとこと）。承認ずみを一般の職員が直すと確認待ちに戻る。内部の記録（家族には出さない）は別の欄。利用者ごとの時系列と印刷
- **連絡帳**（`/care/renraku/`）：その日の家族向けメッセージを並べ、LINE 連携ずみの家族には LINE で送る（送信履歴は LINE 連携の画面）。紙の家族には A4 に 2 人分で印刷（体温・血圧・食事・水分を添える）
- **ヒヤリハット・事故報告**（`/care/incidents/`）：区分・種類・発生日時・場所・けがの程度。メモ（音声・母国語）→「AI で下書き」で状況・原因・対応・再発防止。報告先（家族・医師・管理者・ケアマネ・行政・保険会社）。確認待ち → 承認。報告書を印刷
- **薬の管理**（`/care/medications/`）：利用者ごとの薬（名前・量・のむ時間・目的・処方医・薬局・期間・注意）。更新の期限（次の受診・処方の切れる日）が 14 日以内／過ぎたものをホームと一覧の上に。服薬一覧を印刷
- **通所介護計画書**（利用者のタブ「計画書」）：本人・家族の希望、援助の方針、長期・短期目標、サービス内容の表、健康状態、見直しの時期、説明・同意。前の計画を写して新しく作る。A4 横で印刷。見直しの時期が 30 日以内／過ぎたものをホームに
- **人員配置**（`/care/staffing/`）：日ごとに利用者数・介護職員・看護職員・生活相談員・機能訓練指導員を入れると「安全／確認／要調整」。目安は通所介護の基準（介護・看護職員は利用者 15 人まで 1 人、超えた分は 5 人ごとに 1 人。16 人以上の日は看護職員 1 人。生活相談員・機能訓練指導員 1 人）。細かい決まりは 11 月のパイロットで事業所と決める（`nursing/staffing.py`）
- **送迎表**（`/care/transport/`）：利用の曜日（利用者情報）と送迎の設定（迎え・送り・場所・いつもの車両。`transport` アプリ）から、その日の迎え・送りの一覧と車両ごとの人数（定員超えは赤）。印刷。住所・運転できる職員・乗車定員を見た自動の割り振りは、事業所の条件がそろってから
- **資料・加算の検索**（`/care/docs/`）：施設設定で入れた PDF（加算の手引き・運営規程）を、画面右下の AI アシスタントが根拠のページ付きで答える（`ai_assist` の資料検索をそのまま使う）
- **利用者情報**：コトと同じ介護の形（介護保険証・要介護度・家族／緊急連絡先・カイポケ CSV の取り込み）。利用者のタブは 利用者情報・介護記録・検温板・薬・ヒヤリ／事故・計画書
- **権限**：管理者＝全部、リーダー（権限区分「児発管」を介護の事業所ではこう呼ぶ）＝承認できる、職員＝入力・閲覧
- **設定**（`/care/settings/`）：介護記録・家族向けの文の文字数、文体の希望、発熱とみなす体温、定員
- 請求・予約・来所予定は使わない（請求・LIFE 連携 CSV は後の段階）

## 1. 準備（プロバイダ側。準備中）

- nginx：`kaigonote.yasuragi.ai-labo.cloud` → `127.0.0.1:8047`（HTTPS）
- PostgreSQL：DB `kaigonoteyasuragi`、ユーザー `ai_labo_dbuser`（ゆあーずと同じユーザー）
- アドレス・ポート・DB 名が上と違うときは、Secrets `YASURAGI_DOMAIN`・`YASURAGI_PORT` を登録し、`deploy/.env.yasuragi-aws.example` の `DB_NAME` を直してから配備する

## 2. GitHub Secrets

SSH は同じサーバーなのでゆあーずの `YOURS_DEPLOY_*` をそのまま使います（別にしたいときだけ `YASURAGI_DEPLOY_*`）。

| 名前 | 入れるもの |
|---|---|
| `YASURAGI_ADMIN_PASSWORD` | 管理者 `yasuragi` のパスワード（Manage (yasuragi) の `set_password` で使う。済んだら消してよい） |
| `YASURAGI_DOMAIN`・`YASURAGI_PORT` | アドレス・ポートを変えるときだけ（既定は上の表） |

## 3. 配備（Actions から。サーバーに入らなくてよい）

Actions → **Deploy (yasuragi)** → Run workflow（ブランチ **`yasuragi`**）。

- 初回は `~/kaigonoteyasuragi` に clone し、`.env` を `deploy/.env.yasuragi-aws.example` から作る（`SECRET_KEY` はサーバー上で生成、`DB_PASSWORD`・`ANTHROPIC_API_KEY`・音声の設定は `~/michinoteyours/.env` から写す。ログには項目名だけ）。2 回目以降は `.env` を上書きしない
- 介護施設の機能（`nursing`）が無いコミットを選ぶと止まる。venv は共用なので `requirements.txt` がゆあーずと違うと止まる（先に Deploy (yours)）
- そのあと `deploy/venv-deploy.sh` が `pip install` → `migrate` → `collectstatic` → Gunicorn 起動 → ヘルスチェックまで行う。再起動するのはやすらぎの森の Gunicorn だけ

## 4. 事業所と管理者を作る（初回だけ）

Actions → **Manage (yasuragi)** → `task=create_facility`（事業所名「やすらぎの森」・管理者 `yasuragi` が既定。`with_demo` を付けると架空のサンプルも入る）。そのあと `task=autostart_install` で自動起動・見回り・毎日のバックアップを入れる。

ログインしたら、施設設定で事業所番号・住所・電話・LINE 連携（連絡帳を LINE で送るとき）を入れ、職員・運用管理で職員を追加（承認する人はリーダーか管理者）。利用者はカイポケの CSV（利用者一覧）を「カイポケ CSV から取り込む」で入れるか、手で登録。利用の曜日と送迎の設定も利用者情報で。

## 5. 架空のサンプルデータ

Manage (yasuragi) → `task=demo_add`：利用者 4 人・直近 2 週間の検温板と介護記録（下書き／確認待ち／承認ずみ）・薬・計画書・ヒヤリハット 1 件・人員配置。`task=demo_remove` でそのサンプルだけを消す（備考が【サンプル】の利用者とその記録）。

## 6. 困ったとき

コトと同じ（`docs/DEPLOY_AWS_KOTO.md` 4 章）：Manage (yasuragi) の `error_log`・`status`・`set_media_root`・`backup*`・`speech_check`・`speech_log`。

## 7. これから（打ち合わせの残り）

- 事業所の様式（検温板・連絡帳・日誌）の原本が届いたら、画面と印刷をその形に寄せる
- 記録テンプレート（はい／いいえ・キーワード）の項目を事業所のものに（いまは `nursing/models.py` の `CHECK_ITEMS`）
- 薬：一覧の項目・更新通知のルール・処方箋の出力範囲（事業所の整理待ち）
- 送迎表の自動の割り振り（住所・車両・運転できる職員・乗車定員の条件待ち）
- 人員配置：常勤換算・配置時間・事業所の指定の種類に合わせた判定（11 月のパイロット）
- 請求・加算の範囲と LIFE 連携 CSV（事業所の洗い出し待ち）、役場への提出書式
- 外国人スタッフ向け：画面の文言の多言語化（いまは入力の母国語 → 日本語と確認用の訳）
